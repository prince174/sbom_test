# Идея системы

## Проблема

Находка SCA указывает уязвимый компонент и версию. Разработчик может управлять другим пакетом, который приводит этот компонент транзитивно. Передача строки «пакет + CVE» оставляет ему поиск цепочки, версии обновления и способа проверки.

```text
Находка: @babel/traverse@7.23.0, CVE-2023-45133
Прямая зависимость: @babel/core@7.23.0
Путь: приложение → core → traverse
```

Система связывает находку с действиями в конкретном проекте, сохраняя происхождение каждого вывода.

## Назначение и пользователи

На вход поступает проект Dependency-Track и его находки. На выходе — задача с уязвимым компонентом, подтверждёнными путями, прямыми зависимостями, предлагаемыми изменениями, источниками рекомендаций и критериями приёмки.

Пользователи — AppSec и разработчики. Dependency-Track хранит состав и находки; менеджер пакетов разрешает версии; CI проверяет сборку и тесты; Jira хранит задачи. Система соединяет эти данные в объяснимое задание.

## Сценарий

1. Зафиксировать версию проекта; дождаться обработки SBOM и анализа.
2. Получить находки и UUID уязвимых компонентов.
3. Обойти граф от проекта без заранее выбранного родителя.
4. Найти пути к целевым UUID и первые компоненты после приложения.
5. Получить рекомендации из advisory, метаданных пакетов и файлов проекта.
6. Сформировать план; недостающие сведения отметить как «Требует уточнения».
7. Подготовить черновик задачи. Доставка в Jira — отдельная будущая интеграция.
8. После изменения проверить новый состав, завершённый анализ и результаты CI.

## Три разных вопроса

| Вопрос | Источник ответа | Что ещё не доказано |
|---|---|---|
| Где обнаружена уязвимость? | Находка Dependency-Track | Эксплуатируемость |
| Через что компонент пришёл? | Граф импортированного SBOM | Исправление в новой версии родителя |
| Что изменить? | Advisory, метаданные, manifest/lock-файл | Совместимость без тестов |

Отсутствие пути не отменяет находку. Отсутствие рекомендации не позволяет придумывать исправленную версию. Подавление находки не является устранением уязвимости.

## Пример результата

В Babel-кейсе граф указал на прямую зависимость core. Из advisory извлечён исторический минимум 7.23.2. Из package.json выявлен тестовый override, удерживающий traverse@7.23.0.

Действие: убрать закрепление, обновить core до совместимой версии с исправлением, обновить lock-файл и проверить состав. На стенде выбрана core@7.23.2; npm разрешил traverse@7.29.8, целевая находка исчезла. Это проверка одной CVE, а не рекомендация старой версии Babel на сегодня.

## Границы прототипа

Реализован один npm-сценарий с локальными скриптами и сохранёнными ответами API. Целевой PURL, advisory и часть проверок зафиксированы в коде. Рекомендация извлекается регулярным выражением для конкретного текста.

Не реализованы универсальный сервис, поддержка любых экосистем, общий управляющий процесс, автоматическая проверка совместимости, создание PR, доставка и дедупликация задач Jira.

## Критерии полезности

- Цепочки воспроизводятся по сохранённым рёбрам и UUID находки.
- Конкретные версии исправления имеют проверяемые источники.
- Неполный граф и недоступность данных видны в задаче.
- Повторная обработка не создаёт дубликаты задач.
- Проверка учитывает все затронутые копии и пути.
- Совместимость и применимость CVE не считаются подтверждёнными без результатов проверки.
